MillionSend runs the same on [MillionSend Cloud](https://millionsend.com) and
on your own infrastructure — same dashboard, same API, same SDKs. Pick your
deployment below; the tabs remember your choice across the docs.

## 1. Get MillionSend

<DeploymentTabs>
<DeploymentTab deployment="cloud">

Sign up at [millionsend.com](https://millionsend.com). That's it — no
infrastructure, no AWS account. The dashboard is at
[millionsend.com](https://millionsend.com) and the API at
`api.millionsend.com`.

</DeploymentTab>
<DeploymentTab deployment="self-hosted">

You need Docker (with Compose), Node 18+, and an AWS account with SES access.
New AWS accounts start in the SES sandbox, which can only send to verified
recipients — [request production access](https://docs.aws.amazon.com/ses/latest/dg/request-production-access.html)
to send to anyone.

One command, in an empty directory — no clone needed:

```sh
mkdir millionsend && cd millionsend
npx @millionsend/setup
```

The wizard detects what is already in the directory and offers each step:
create `.env` with generated secrets, provision the AWS resources (IAM user +
policy, SNS event topic, SES configuration set — and an SQS events queue when
your deployment has no public HTTPS URL), then download the compose file and
start the prebuilt image with `docker compose up -d`. Every step is skippable
and safe to re-run; `--dry-run` prints the full plan and touches nothing.

When it finishes: dashboard at `http://localhost:3000`, API at
`http://localhost:3001`. The first user to register becomes the initial
account — after that, signup is closed unless you opt in. Prefer doing it by
hand, or ready for production? See [Self-hosting](/self-hosting).

</DeploymentTab>
</DeploymentTabs>

## 2. Verify a sending domain

MillionSend only sends from domains you have verified.

1. In the dashboard, go to **Domains** and add a domain you control
   (e.g. `acme.dev`).
2. Add the DNS records it shows you — a DKIM TXT record plus MAIL FROM
   records — at your DNS provider.
3. Click **Verify DNS records**. MillionSend also resolves the records live,
   so you can see immediately which ones are still missing.

## 3. Create an API key

Go to **API keys** and create one. The `ms_` token is shown once — copy it
now. Keys can be scoped to full access or sending-only, and optionally pinned
to a single domain.

## 4. Send an email

Your API base URL:

<DeploymentTabs>
<DeploymentTab deployment="cloud">

`https://api.millionsend.com`

</DeploymentTab>
<DeploymentTab deployment="self-hosted">

Your instance's API origin — `http://localhost:3001` on a local compose
setup, or the hostname your reverse proxy serves the API on (`PUBLIC_API_URL`,
e.g. `https://api.acme.dev`). The examples below use the Cloud URL; swap in
yours.

</DeploymentTab>
</DeploymentTabs>

With curl:

```sh
curl -X POST https://api.millionsend.com/emails \
  -H "Authorization: Bearer ms_..." \
  -H "Content-Type: application/json" \
  -d '{
    "from": "Acme <onboarding@acme.dev>",
    "to": ["delivered@example.com"],
    "subject": "Hello from MillionSend",
    "html": "<strong>It works!</strong>"
  }'
```

Or with the Node SDK (`npm install millionsend`):

```ts
import { MillionSend } from "millionsend";

const ms = new MillionSend("ms_...", { baseUrl: "https://api.millionsend.com" });

const { data, error } = await ms.emails.send({
  from: "Acme <onboarding@acme.dev>",
  to: "delivered@example.com",
  subject: "Hello from MillionSend",
  html: "<strong>It works!</strong>",
});

if (error) console.error(error.name, error.message);
else console.log("sent", data.id);
```

Both return `{ "id": "..." }`. Watch the email move from `queued` to
`delivered` on the **Emails** page.

<Callout type="info">
On a self-hosted instance, delivery events (delivered, bounced, complained)
require the SES event pipeline the setup wizard configures — see
[Self-hosting → SES events](/self-hosting#ses-events-bounces-complaints-deliveries).
On Cloud they flow automatically.
</Callout>

Already on Resend? Point the official Resend SDK at MillionSend instead — set
`RESEND_BASE_URL` to your base URL and use your `ms_` key. The wire format is
identical.

title: SDKs
description: SDKs oficiais do MillionSend para nove linguagens, publicados sob MIT.
---

Cada SDK espelha o formato do SDK oficial correspondente do Resend, então
migrar é quase um localizar-e-substituir: troque o import/classe e aponte a
URL base para o MillionSend. Todos os SDKs são licenciados sob MIT e vivem em
repositórios próprios na
[organização MillionSend no GitHub](https://github.com/MillionSend).

Como a API é compatível com a do Resend, os SDKs oficiais do
Resend também funcionam — aponte-os para o MillionSend pela opção de URL base
(ex.: `RESEND_BASE_URL`). A partir da 0.9.0, todo SDK do MillionSend também
cobre os [e-mails recebidos e as caixas de entrada](#recebimento-e-caixas-de-entrada).

## URL base

<DeploymentTabs>
<DeploymentTab deployment="cloud">

`api.millionsend.com` — o que todos os exemplos desta página usam, e o padrão a partir do SDK 0.5.0: sem uma URL base configurada, o SDK fala com o MillionSend Cloud.

</DeploymentTab>
<DeploymentTab deployment="self-hosted">

A origem da API da sua instância (ex.: `https://api.acme.dev`, ou
`http://localhost:3001` localmente). Todo SDK a recebe pela mesma opção em
que os exemplos passam a URL da Nuvem — `baseUrl` / `base_url` / `BaseURL`
conforme a convenção da linguagem — e o SDK de Node também lê a variável de
ambiente `MILLIONSEND_BASE_URL`. Veja
[Auto-hospedagem](/pt-BR/self-hosting) para implantar a instância em si.

Todo SDK recusa uma URL base em `http://` puro, a menos que o host seja
loopback (`localhost`, `127.0.0.1`, `::1`): uma chave de API enviada em texto
puro para outra máquina é uma chave de API exposta na rede. Uma instância
acessada por HTTP puro em uma rede privada exige o opt-in de cada SDK — Node
`allowInsecureHttp`, Python `allow_insecure_http`, Go `AllowInsecureHTTP`,
Ruby `allow_insecure_http`, PHP a opção `allowInsecureHttp`, Rust
`allow_insecure_http()`, Java o construtor de três argumentos, .NET
`AllowInsecureHttp`, Elixir `allow_insecure_http` — ou, melhor, um reverse
proxy TLS na frente dela.

</DeploymentTab>
</DeploymentTabs>

## Node.js / TypeScript

[`millionsend` no npm](https://www.npmjs.com/package/millionsend) — Node 18+.

```sh
npm install millionsend
```

```ts
import { MillionSend } from "millionsend";

const ms = new MillionSend("ms_123", { baseUrl: "https://api.millionsend.com" });

const { data, error } = await ms.emails.send({
  from: "Acme <onboarding@acme.dev>",
  to: "delivered@example.com",
  subject: "Hello from MillionSend",
  html: "<strong>It works!</strong>",
});
```

## Recebimento e caixas de entrada

A partir da 0.9.0, todo SDK lê os [e-mails recebidos](/pt-BR/concepts/receiving)
e trabalha com as [caixas de entrada](/pt-BR/concepts/inboxes), com a mesma
árvore no jeito de cada linguagem (os nomes abaixo são os do Node):

| Recurso | Métodos |
| --- | --- |
| `emails.receiving` | `list` (com `wait`, `since`, `inboxId`, `to`, `from`, `subjectContains`, `unread`, `includeQuarantined`), `get`, `reply`, `forward`, `remove` |
| `emails.receiving.attachments` | `list`, `get` |
| `inboxes` | `create`, `list`, `get` (pelo id ou pelo endereço), `update`, `remove` |
| `inboxes.safety` | `get`, `update` |
| `inboxes.codes` | `latest` (com `from`, `wait`, `maxAge`) |
| `inboxes.quarantine` | `list`, `release` (com `trustSender`) |
| `inboxes.labels` | `list`, `create`, `update`, `remove` |
| `inboxes.threads` | `list`, `search`, `get`, `update`, `remove` |
| `inboxes.threads.emails` | `list`, `get`, `reply`, `forward` |
| `inboxes.drafts` | `list`, `create`, `get`, `update`, `remove`, `send`, `reject` |

```ts
import { MillionSend } from "millionsend";

const ms = new MillionSend("ms_123");

// Espera até 30 segundos pelo próximo e-mail entregue numa caixa.
const { data: page } = await ms.emails.receiving.list({ inboxId: "7eeb9517-aed7-40d7-ad65-500be42ed147", wait: 30 });

// O código de verificação ou link de acesso mais recente que ela recebeu.
const { data: code } = await ms.inboxes.codes.latest("7eeb9517-aed7-40d7-ad65-500be42ed147", { wait: 30 });
```

- Responder, encaminhar e enviar rascunhos aceitam uma chave de
  idempotência, e o SDK manda uma por você.
- Uma resposta ou um encaminhamento que as regras da caixa retêm devolve um
  rascunho em vez do e-mail enviado, e os SDKs dizem qual dos dois veio: no
  Node o resultado traz `kind: "sent"` ou `kind: "draft"`, e cada linguagem
  tem o equivalente.
- Campos e valores de enum desconhecidos são mantidos ou ignorados, nunca
  viram erro, então uma API mais nova não quebra um SDK mais antigo.
- Os domínios ganham `receiving_catch_all`, as chaves de API `inbox_id`, os
  webhooks `inbox_ids`, e os tipos de evento de webhook ganham o
  `email.received` e os eventos das caixas.

---
title: Segmentos
description: Filtros salvos sobre seus contatos, usáveis como alvo de transmissões.
---

Um segmento é um **filtro salvo** sobre os contatos da equipe — ele armazena
uma expressão de filtro, não uma lista de membros. Quem faz parte do segmento é avaliado
ao vivo: um contato que passa a corresponder ao filtro entra no segmento
imediatamente, e a contagem de contatos que você vê é computada no momento da
leitura.

Um segmento criado **sem filtro** é uma **lista manual de membros**: você
adiciona e remove contatos explicitamente (pelo painel, ou via
`POST /contacts/{id}/segments/{segmentId}` e o `add_contact_to_segment` do MCP). Os dois
tipos valem igualmente como alvo de transmissões.

Os filtros atuam sobre campos do contato (e-mail, nome, estado de inscrição,
data de criação) e sobre
[propriedades personalizadas](/pt-BR/concepts/contacts#o-que-um-contato-armazena),
com operadores como igual, contém, definido / não definido e comparações de
data. As condições combinam com e/ou.

## Datas

`created_at` e qualquer propriedade aceitam quatro operadores de data:

| Operador | Pega a data que | Valor |
| --- | --- | --- |
| `before` | vem antes do valor | Uma data ou data e hora ISO 8601 |
| `after` | vem depois do valor | Uma data ou data e hora ISO 8601 |
| `in_last_days` | fica entre N dias atrás e agora | N, de 1 a 36500 |
| `not_in_last_days` | é de mais de N dias atrás | N, de 1 a 36500 |

```json
{
  "match": "all",
  "conditions": [
    { "field": "property:last_login", "op": "not_in_last_days", "value": "90" }
  ]
}
```

A propriedade é lida como data do mesmo jeito que uma
[propriedade de data](/pt-BR/concepts/contacts#tipos-de-propriedade) aceita
uma. Um valor que não é data não entra em nenhum desses operadores, e uma
data que ainda vai chegar não entra em `in_last_days` nem em
`not_in_last_days`. Para achar contatos sem a propriedade, use `is_not_set`.
Os operadores de texto valem para qualquer propriedade, seja qual for o tipo.
No painel, os operadores de data aparecem para `created_at` e para as
propriedades de data.

## Usando segmentos

- **Transmissões** — envie para um segmento em vez de todos os contatos. O fan-out
  resolve quem faz parte do segmento no momento do envio usando o mesmo tradutor de
  filtros da contagem de contatos, então o que você prevê é o que sai.
- **Filtro no painel** — a visão de Contatos pode ser filtrada por segmento,
  e a exportação CSV respeita o filtro de segmento ativo.

## API

`POST/GET/PATCH/DELETE /segments` e `GET /segments/{id}` (que inclui o
`contact_count` ao vivo) — veja a [referência da API](/pt-BR/api-reference).
Expressões de filtro inválidas são rejeitadas com `422` e nunca armazenadas.
Um `PATCH` sem `name` e sem `filter` também recebe `422`.
